## Social Proof Popup - Recent Purchases

### Overview
A popup that displays recent purchases to create social proof and encourage conversions.

### Features
- Shows buyer's first name, last initial, city, state, product name, and time ago
- Only displays if there's a real purchase within the last 5 hours
- Test mode available with `?test=socialproof2024` URL parameter

### Files Modified

- `/public/index.php` - Added route `/api/recent-purchases`

### Mobile Fix (Important)

## Google Merchant Feed Generator

### Overview
Auto-generates Google Shopping feed XML with proper color, size, gender, and age_group attributes.

### Script Location
`/scripts/generate-google-feed.php`

### Output
`/public/google-merchant-feed.xml`

### Features
- Creates separate items for each color variant (Google best practice)
- Groups variants with `g:item_group_id`
- Auto-detects gender from product name (women's, men's, ladies, etc.)
- Defaults to "unisex" for apparel when gender not detected
- Always sets `g:age_group` to "adult" for apparel
- Skips products with zero inventory
- Includes shipping dimensions and free shipping info

### Cron Job


## Multi-Item Shipping System

### Overview
Complete shipping calculation system for multiple items with separate rates for Standard and Express shipping.

### Database Change
```sql
ALTER TABLE products ADD COLUMN shipping_price_additional DECIMAL(8,2) DEFAULT NULL AFTER shipping_price;
UPDATE products SET shipping_price_additional = 2.00 WHERE shipping_price IS NOT NULL AND shipping_price > 0;
```

### How Standard Shipping Works
- **First item**: Pays full `shipping_price` (highest among cart items)
- **Additional items**: Pay `shipping_price_additional` rate (default $2.00)
- **Free shipping items**: Do not factor into calculation at all

### How Express Shipping Works
- Uses the same additional-item logic as Standard
- Adds an **Express premium** = (Express zone flat rate - Standard zone flat rate)
- Example: If Express flat is $12.99 and Standard flat is $5.99, premium is $7.00

### Example (Zone 1, 3 t-shirts with $6.99 shipping, $2.00 additional)
| Method | Calculation | Total |
|--------|-------------|-------|
| Standard | $6.99 + $2.00 + $2.00 | **$10.99** |
| Express | $10.99 + ($12.99 - $5.99) | **$17.99** |

### Files Modified
- `/app/Core/Shipping/ShippingCalculator.php` - Updated `getShippingOptions()` and `getRate()` methods
- `/app/Models/Cart.php` - Added `shipping_price_additional` to SELECT query
- `/app/Controllers/ShippingController.php` - Added `shipping_price_additional` to items array
- `/app/Models/ShippingMethod.php` - Added `getStandardForZone()` method

### Key Code Logic
```php
// Calculate fixed shipping: highest rate for first item, additional rate for rest
usort($fixedShippingItems, fn($a, $b) => $b['shipping_price'] <=> $a['shipping_price']);

$firstItemProcessed = false;
foreach ($fixedShippingItems as $fsi) {
    if (!$firstItemProcessed) {
        $fixedShippingTotal += $fsi['shipping_price'];
        if ($fsi['quantity'] > 1) {
            $fixedShippingTotal += $fsi['shipping_price_additional'] * ($fsi['quantity'] - 1);
        }
        $firstItemProcessed = true;
    } else {
        $fixedShippingTotal += $fsi['shipping_price_additional'] * $fsi['quantity'];
    }
}

// For Express, add premium on top
if ($isExpress) {
    $expressPremium = max(0, $expressFlatRate - $standardFlatRate);
    $rateInfo['rate'] = round($fixedShippingTotal + $expressPremium + $handlingFees, 2);
} else {
    $rateInfo['rate'] = round($fixedShippingTotal + $handlingFees, 2);
}
```

### Admin Notes
- Set `shipping_price` and `shipping_price_additional` for products to use fixed shipping logic
- Products with NULL shipping_price use zone-based rates instead
- T-shirts default to $6.99 shipping + $2.00 additional

## Coupon Discount Recalculation on Cart Change

### Issue
When a coupon was applied and then more items were added to cart, the discount amount stayed the same instead of recalculating based on the new cart total.

### Solution
The checkout page now recalculates the coupon discount whenever it loads, based on the current cart total.

### Files Modified
- `/app/Controllers/CheckoutController.php` - Added discount recalculation in `index()` method

### Code Added
```php
// Recalculate coupon discount if one is applied (in case cart changed)
if (!empty($_SESSION['applied_coupon'])) {
    $coupon = $_SESSION['applied_coupon'];
    if ($coupon['type'] === 'percentage') {
        $newDiscount = round($cartTotal * ($coupon['value'] / 100), 2);
    } elseif ($coupon['type'] === 'fixed') {
        $newDiscount = min($coupon['value'], $cartTotal);
    }
    $_SESSION['applied_coupon']['discount'] = $newDiscount;
}
```

## Checkout - Stripe Email Variable Fix

### Issue
The `email` variable used in `stripe.confirmPayment()` was defined locally inside `initializePayment()` but referenced in the form submit handler, causing it to be undefined.

### Fix
Read the email from the DOM at submit time instead of referencing a variable from another function's scope.

### Files Modified
- `/app/Views/checkout/index.php` - Fixed email variable in form submit handler

### Code Change
**Before (broken):**
```javascript
// Handle form submission
document.getElementById('checkoutForm').addEventListener('submit', async function(e) {
    // ...
    const { error, paymentIntent } = await stripe.confirmPayment({
        elements,
        confirmParams: {
            return_url: window.location.origin + '/checkout/confirm',
            receipt_email: email,  // email was undefined here!
        },
        redirect: 'if_required'
    });
```

**After (fixed):**
```javascript
// Handle form submission
document.getElementById('checkoutForm').addEventListener('submit', async function(e) {
    // ...
    // Get email from form at submit time
    const customerEmail = document.getElementById('email').value.trim();

    const { error, paymentIntent } = await stripe.confirmPayment({
        elements,
        confirmParams: {
            return_url: window.location.origin + '/checkout/confirm',
            receipt_email: customerEmail,
        },
        redirect: 'if_required'
    });
```

**2FA Login Session Bug Fix (Important!):**

The 2FA login flow stores pending verification in `$_SESSION['pending_2fa_admin']`. A critical bug was discovered where adding a "Cancel" link with inline PHP:

```php
<!-- WRONG - PHP executes on page load, not on click! -->
<a href="/admin/login" onclick="<?php unset($_SESSION['pending_2fa_admin']); ?>">Cancel</a>
```

This caused the session to be cleared immediately when the page loaded, before the user could submit the 2FA code. The login would loop back to the start.

**Fix:** Create a separate route/controller method for cancellation:

```php
// In AuthController.php
public function cancel2FA(): void
{
    unset($_SESSION['pending_2fa_admin']);
    $this->redirect('/admin/login');
}

// In index.php routes
$router->get('/admin/2fa/cancel', [Admin\AuthController::class, 'cancel2FA']);
```

Then the view uses a simple link:
```php
<a href="/admin/2fa/cancel">Cancel and start over</a>
```

**Sidebar Link:**
Added "2FA Security" link in `/app/Views/layouts/admin.php` sidebar footer for easy access to 2FA settings.
