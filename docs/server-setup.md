# Server setup

The web installer checks requirements; it does not run sudo or install host packages.
Never grant sudo access to the web-server account.

## Debian and Ubuntu

From the Apparix installation directory, preview missing dependencies:

```sh
bash tools/setup-server.sh --php=8.3
```

Match `--php` to the PHP version shown in the web installer, not necessarily the
server's default CLI version. PHP 8.3 or newer must be available from your trusted
OS repositories. The tool does not add repositories or upgrade the OS.

To apply the plan, choose the actual non-root PHP worker user:

```sh
sudo bash tools/setup-server.sh --php=8.3 --owner=www-data --fix-permissions --apply
```

The default run changes nothing. Applying requires typing `INSTALL`, then approving
the package manager's transaction. Only missing packages are requested; package
dependencies can also be installed or upgraded. Package hooks may start/restart
services, so use a maintenance window on shared servers. Already-installed but
disabled extensions are reported for manual configuration, not silently enabled.

Optional flags for a new server:

- `--with-nginx`: install Nginx and the selected PHP-FPM version if absent. Does
  not configure the website, change existing vhosts, or replace Apache.
- `--with-mariadb`: install a local MariaDB server if absent. Omit for an existing
  or remote database. Database creation, users and credentials remain manual.
- `--with-cron`: install the cron daemon if absent. No jobs are added or replaced.

Do not install a second web/database server on an already configured host without
reviewing port conflicts. Existing vhost files, database contents, firewall rules,
repositories and crontabs are not rewritten by the tool.

Composer installs the locked production dependencies as the application user,
with scripts/plugins disabled. Permission repair is explicit, limited to this
installation, skips `.git`, and does not follow symlinks or cross filesystems.
It preserves existing private key permissions and sets `.env` to mode 0600.
Symlinked/mounted data and unusual hosting layouts need administrator review.
Code files must be writable by the selected PHP worker for in-app updates.

The final check runs as the application user. Reload the browser's requirements
step afterward: CLI and PHP-FPM can use different extensions/configuration.
The tool does not automatically restart existing PHP-FPM services. Your server
administrator may need to reload the correct pool after extension installation.

## Docker

Use the dependencies built into the Apparix Docker image and its database service.
Install Docker/Compose on the host separately. Do not run this helper inside a
container. Rebuild/update the image to change its system dependencies; an Apparix
application update does not rebuild the image.

## Shared hosting and other operating systems

Ask your host to enable the missing PHP extensions shown by the installer and
provide PHP 8.3+, a compatible database, HTTPS, and Composer dependencies. Use the
host's PHP selector and scheduled-task panel. No privileged browser workaround is
provided. This helper deliberately refuses unsupported package managers.

## Remaining setup

Complete the browser installer, configure SMTP and payment/API credentials, and
verify HTTPS. Review `setup-cron.sh` generated by installation before running it;
confirm its user and entries match your hosting environment. Plugin-specific
workers must be configured from each plugin's instructions. The dependency tool
does not enable plugins, submit orders, install cron jobs, or change production
automation settings.
